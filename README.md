Backend & Android розробник із Чернігова. Сім років працюю з мережами й технічною
підтримкою в телеком-компанії «Основа»; паралельно доводжу власні продукти до
живих користувачів — від Kotlin-застосунків у продакшені до асинхронних бекендів

Код лежить у приватних репозиторіях; тут — опис і скріншоти.

## HelpLoop

Q&A-спільнота для айтівців: питай, на чому застряг, відповідай на те, що вже вирішив.
Інтерфейс український, кодова база — англійською. У продакшені.

| | | |
|---|---|---|
| ![Головна](assets/helploop/home.png) | ![Вхід](assets/helploop/login.png) | ![Новини](assets/helploop/updates.png) |

**Що робить.** Питання й відповіді з markdown, підсвіткою коду, тегами,
коментарями, голосуванням, прийнятими відповідями й репутацією. Акаунти з
підтвердженням пошти, скиданням пароля, керуванням сесіями та самостійним
видаленням. Повнотекстовий пошук на індексі PostgreSQL. Модерація: черга скарг,
закриття/відкриття, м'яке видалення з відновленням, блокування акаунтів.
Адмінка на `/admin` — користувачі, контент, теги й append-only журнал дій.

**Як влаштований.** Next.js 15 з App Router: сторінки рендеряться на сервері,
замість окремого API — server actions. Автентифікація зроблена руками —
непрозорі серверні сесії, які відкликаються одним `DELETE`, без залежності від
beta-бібліотек авторизації. Паролі — `scrypt` зі стандартної бібліотеки Node
(memory-hard, без нативного модуля, який ламав би збірку між Alpine і Windows).
Захист від ботів — self-hosted Altcha (proof of work), без третіх сторін і
трекінгу. Пошук — на індексі з `simple`-словником: готового українського
стемера в Postgres немає, а англійський дає хибні збіги в обидва боки.

**Стек.** Next.js 15 (App Router), React 19, TypeScript (strict), PostgreSQL 16
+ Prisma, Tailwind CSS v4, remark/rehype для markdown, highlight.js, zod, sharp,
Resend (пошта через HTTP API), Caddy, Docker Compose.

## ФОП Фінанси

Офлайн-застосунок обліку фінансів для українських ФОП і ТОВ: доходи й витрати,
податки за сімома системами оподаткування, аналітика рентабельності, калькулятор
найму та календар платежів. Опублікований у Google Play з покупками.

| Облік | Аналітика | Калькулятор найму |
|---|---|---|
| ![Облік](assets/fop-finance/dashboard.png) | ![Аналітика](assets/fop-finance/analytics.png) | ![Найм](assets/fop-finance/hiring.png) |

| Календар | Порівняння систем |
|---|---|
| ![Календар](assets/fop-finance/calendar.png) | ![Порівняння](assets/fop-finance/comparison.png) |

**Що робить.** Доходи й витрати з категоріями, операції у валюті з автоматичним
курсом НБУ на дату, регулярні шаблони. Рахунки з залишками, клієнти й рахунки-фактури
з PDF, книга обліку доходів за квартал. Сім систем оподаткування, кожна зі своїм
розкладом платежів, лімітами й попередженнями про перевищення. Аналітика: маржа,
рентабельність, точка беззбитковості, прогноз потоку, порівняння з галуззю.
Калькулятор найму (штат / Дія.City / ФОП-підрядник) і календар зі строками сплати.

**Як влаштований.** Local-first за задумом: усі фінансові записи лежать у базі на
пристрої й нікуди не передаються — немає сервера, немає й витоку. Єдиний вихід у
мережу — курс НБУ на дату валютної операції. Захист входу: біометрія та код
доступу, що зберігається лише як незворотний хеш. Регулярні платежі й нагадування —
на WorkManager у фоні.

**Стек.** Kotlin, Jetpack Compose (Material 3), Navigation Compose, Room,
WorkManager, AndroidX Biometric, DocumentFile, Google Play Billing, AdMob +
User Messaging Platform (згода на рекламу).

## Osnova TV

Android-клієнт для абонентів кабельного оператора: особистий кабінет, оплата,
перегляд IPTV. Роздається власним APK з окремим каналом оновлень — без Google Play.

| Вхід | Обліковий запис | Фінансова історія |
|---|---|---|
| ![Вхід](assets/osnova-tv/login.png) | ![Обліковий запис](assets/osnova-tv/account.png) | ![Фінансова історія](assets/osnova-tv/finance.png) |

| Тарифні плани | Телебачення IPTV | Додаткові послуги |
|---|---|---|
| ![Тарифи](assets/osnova-tv/tariffs.png) | ![IPTV](assets/osnova-tv/iptv.png) | ![Послуги](assets/osnova-tv/extra.png) |

> На екрані облікового запису особовий рахунок, ПІБ, логін, адреса й IP замазані —
> це реальні дані абонента.

**Що робить.** Вхід до особистого кабінету, баланс і тарифи, перегляд IPTV-каналів
із програмою передач, нагадування про стан рахунку. Дані кабінету застосунок читає
з вебсторінки оператора, розбираючи HTML — окремого API оператор не надає.

**Як влаштований.** Клієнт на Compose парсить особистий кабінет через jsoup, тягне
плейлист (M3U) і програму (XMLTV) та відтворює потоки через libVLC. Firebase Cloud
Messaging — для сповіщень; токен зберігається зашифровано (EncryptedSharedPreferences).
Окремий бекенд на Python (aiohttp + aiogram) приймає реєстрації пристроїв, розсилає
сповіщення через firebase-admin і роздає APK. Автооновлень від Google Play немає,
тож канал оновлень свій: `version.json` віддає версію та посилання, а застосунок
перед установкою звіряє завантажений APK за SHA-256 — щоб підсунути підмінений файл
не вийшло.

**Стек.** Kotlin, Jetpack Compose (Material 3), jsoup, OkHttp, libVLC
(`org.videolan.android:libvlc-all`), Firebase Cloud Messaging, AndroidX
Security-Crypto, Biometric, WorkManager. Бекенд: Python, aiohttp, aiogram,
firebase-admin, SQLite, Caddy.

## Табель

Android-застосунок, який читає робочий табель із Google-таблиці й показує, хто з
тобою на зміні цього дня, а також рахує зарплату за місяць. Зроблено під конкретний
графік: доба через дві, решта колективу — плаваючий графік по 8 і 11 годин.

| Зміна | Місяць | Люди |
|---|---|---|
| ![Зміна](assets/tabel/shift.png) | ![Місяць](assets/tabel/month.png) | ![Люди](assets/tabel/people.png) |

| Підсумки | Зарплата |
|---|---|
| ![Підсумки](assets/tabel/totals.png) | ![Зарплата](assets/tabel/salary.png) |

> Прізвища колег і суми на скріншотах замазані — це реальні дані з таблиці.

**Що робить.** На обрану дату показує твій статус і всіх, хто працює того ж дня,
згрупованих за типом зміни. Календар графіка з підсумком за місяць. Список колективу
з гортанням по місяцях і прогнозом для місяців, яких ще немає в таблиці. Підсумки за
рік і за весь час: години, доби, вихідні, з ким найчастіше збігаються зміни.
Розрахунок зарплати з поясненням формули та історією за 12 місяців. Сповіщення в день
зміни й віджет зі статусом на сьогодні.

**Як влаштований.** Джерело даних — Google-таблиця табеля; застосунок читає її й
розкладає ротацію «доба через дві». Для майбутніх місяців, яких ще немає в таблиці,
склад і доби добираються прогнозом за ротацією. Віджет на головному екрані — на
Glance. Сповіщення — на WorkManager.

**Стек.** Kotlin, Jetpack Compose (Material 3), Glance (віджет), WorkManager,
Lifecycle ViewModel. Без бекенду — читає таблицю напряму.

## Домашня бібліотека fb2

Каталогізує локальну папку з книгами, сам розбирається в серіях і версіях томів і
збирає архіви. Керування — через Telegram Mini App, бота або CLI. Джерело даних —
тільки твої файли на диску, нічого нікуди не викачується.

| Mini App | CLI |
|---|---|
| ![Mini App](assets/bookshelf/miniapp.png) | ![CLI](assets/bookshelf/cli.png) |

**Що робить.** Читає метадані з самих fb2 (автор, серія, номер тома, анотація,
обкладинка), прозоро розгортаючи `.fb2.zip`. Зводить серії, побиті різнобоєм у
даних. З кількох копій одного тома лишає актуальну — за датою й обсягом, решту
позначає застарілими, але не видаляє. Показує пропуски в нумерації. Збирає ZIP по
всій бібліотеці, серії чи автору, ріжучи на частини під ліміт Telegram.

**Як влаштований.** Ядро — Python-бібліотека з CLI (`scan`, `stats`, `series`,
`duplicates`, `pack`). Повторний `scan` перечитує лише змінені файли. Поверх —
Telegram-бот на aiogram і вебзастосунок (Mini App) на FastAPI, які працюють з тим
самим каталогом. Метадані кешуються в SQLite.

**Стек.** Python, FastAPI + uvicorn (Mini App), aiogram (бот), SQLite, власний
парсер fb2/`.fb2.zip`.

## SQLi-сканер

Набір інструментів, щоб власник сайту міг перевірити свої ресурси на SQL-ін'єкції
й зрозуміти, як їх виправити. Свідомо обмежений: тільки власні сайти або з
письмовим дозволом.

| HTML-звіт |
|---|
| ![Звіт](assets/sqli-scanner/report.png) |

**Що робить.** Шукає SQL-ін'єкції трьох типів: error-based (за появою помилки СУБД),
boolean-based blind (за різницею відповідей на істинний і хибний вираз) і time-based
blind (за штучною затримкою). Перевіряє різні вектори — параметри URL, поля форм,
заголовки, cookie, шлях. Визначає СУБД (MySQL/MariaDB, PostgreSQL, MS SQL, Oracle,
SQLite) і добирає під неї пейлоади. Звіт у HTML і JSON. Окремий `REMEDIATION.md` —
як закрити знайдені діри, з прикладами коду на Java, PHP і Node.js.

**Як влаштований.** Чистий Python 3 без зовнішніх залежностей — вистачає
стандартної бібліотеки. У комплекті навмисно вразливий міні-сайт, щоб перевірити,
що сканер працює. Запуск — через CLI, скрипт автозапуску з меню або Telegram-бот.
«Розумний рушій» відрізняє помилку СУБД у відповіді від звичайного тексту.

**Стек.** Python 3 (лише stdlib), Telegram-бот на чистому Bot API.

## Upwork Copilot

Комплект Python-скриптів для пошуку, оцінки та обробки вакансій на Upwork під стек
Python / автоматизація / API. Збирає вакансії, рахує відповідність і генерує
супровідні листи.

| CLI |
|---|
| ![CLI](assets/upwork-copilot/cli.png) |

**Що робить.** Збирає вакансії з email-алертів Upwork (по IMAP), з локальних файлів
і через Telegram-бот. Рахує match score від 1 до 10 за ключовими словами з
поясненням, звідки оцінка. Ловить red flags (безоплатні тестові, нереальний бюджет)
і не-твій стек. Зберігає все в JSON або SQLite. Генерує персоналізований cover letter
під вакансію за структурою Hook → Solution → CTA. Працює як через CLI-команди, так і
через інтерактивне меню.

**Як влаштований.** Ядро на чистому Python 3.8+ — без залежностей воно падає на
`urllib` + `xml.etree`; `feedparser` і `requests` роблять роботу з фідами
надійнішою, але не обов'язкові. Скоринг — прозорий: кожен бал видно в розбивці за
правилами (`+6 python_core`, `+7 bots`, `+3 budget`).

**Стек.** Python 3.8+, IMAP (email-алерти), feedparser + requests (опційно),
Telegram Bot API, JSON/SQLite.

|---|
